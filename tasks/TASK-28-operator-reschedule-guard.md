# TASK-28 — оператор: завершённый визит не переносится

Находка приёмки прогона `g_20260808-181728`, **P1**: перенос предлагается для любой занятой
ячейки без проверки статуса записи ([slot-card.tsx:353]). Поскольку `completed` входит в
занятость расписания, оператор может выбрать **завершённый** визит и перенести его: `PATCH`
без `status` примет новые `doctorId` и `start` — то есть у закрытого медицинского визита
задним числом меняются врач и время.

## Файлы

- `src/pages/operator/slot-card.tsx`
- `src/pages/operator/operator-page.tsx`
- `src/pages/operator/reschedule-guard.test.tsx`

## Вход

TASK-26

## Готовность

1. Перенос и отмена предлагаются только для записей в нетерминальных статусах;
   терминальность берётся из общего модуля (TASK-26).
2. Новый интервал переноса проверяется теми же правилами, что и создание: внутри смены,
   в опубликованной неделе, к работающему врачу. Отказ сервера показывается текстом.
3. Тест доказывает: у завершённой записи переноса нет; перенос за пределы смены
   отклоняется и объясняется; перенос в свободный слот внутри смены проходит.
