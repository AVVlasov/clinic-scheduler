# TASK-08 — АРМ администратора

Макет: `ai/05-дизайн/Clinic-scheduler UI макеты/ARM-admin.dc.html`. Администратор площадки
режет расписание на неделю вперёд и ведёт справочник врачей. Ошибка здесь стоит не одного
визита, а недели работы площадки.

## Файлы

- `src/pages/admin/index.ts`
- `src/pages/admin/admin-page.tsx`
- `src/pages/admin/week-templates.tsx`
- `src/pages/admin/doctors-directory.tsx`
- `src/pages/admin/admin-page.test.tsx`

## Вход

TASK-02, TASK-04

## Готовность

1. Шаблоны приёма на неделю: таблица «врач × день» с интервалами, публикация недели с
   подтверждением и видимым итогом («нарезано N слотов на M врачей»).
2. Справочник врачей: список, карточка врача (специальности, основная площадка, кабинет,
   временные площадки, правила приёма, допуски к оборудованию), сохранение через клиент API.
3. Тест доказывает: таблица шаблонов пришла из данных, публикация недели вызывает запрос и
   показывает итог, правка карточки врача сохраняется и отражается в списке.

## Проверки

```
npx --no-install tsc --noEmit
npx --no-install eslint ./src --max-warnings=0
npx --no-install vitest run src/pages/admin
```

## Что учесть

- Публикация недели необратима по смыслу: подтверждение обязательно, а итог должен называть
  числа, а не «готово».
- Незаполненные карточки врачей — счётчик в шапке макета; он считается по данным, а не
  захардкожен.
