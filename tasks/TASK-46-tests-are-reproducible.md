# TASK-46 — прогон воспроизводим: тесты не читают стенные часы

Одиннадцать тестовых файлов берут «сейчас» из системных часов и не подменяют время.
Следствие наблюдалось: в воскресенье набор краснел семью тестами, в будни был зелёным.
Шесть дней из семи гейт ничего не замечал, поэтому дефекта как бы не существовало — а
вердикты выносились в разные дни недели, и часть из них доказывала не то, что задумано.

Недетерминированный тест хуже отсутствующего: он даёт зелёный сигнал, не связанный с
состоянием кода, и обесценивает весь набор — красный прогон начинают объяснять словами
«ну оно иногда падает».

Два круга приёмки (TASK-24, TASK-34) ушли на дефекты этого класса, и оба «починили» их
сдвигом точки отсчёта, а не устранением зависимости.

## Готовность

1. Ни один тест не берёт текущее время из системных часов: дата либо зафиксирована
   (`vi.setSystemTime`), либо передана параметром.
2. Правило гейта проходит с принудительно включённым признаком:
   `BCF_TIME_DEPENDENT_TESTS=1 pwsh harness/lint-gate.ps1` — зелено.
   `new Date()` / `Date.now()` / `today()` в тестовом файле без подмены времени —
   нарушение. **Обвязку не трогай:** флаг в `.claude/hooks/hooks-config.json` включает
   владелец после закрытия задачи, а доказывается она переменной окружения.
3. Полный набор зелёный при прогоне с зафиксированным воскресеньем **и** с
   зафиксированным понедельником: два прогона дают одинаковый результат.
4. Стаб не зависит от дня старта процесса: демо-данные строятся от заданного окна, а не
   от того, когда запустили сервер (закрывается TASK-36; здесь — тест на это).
