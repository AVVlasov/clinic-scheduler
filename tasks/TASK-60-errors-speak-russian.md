# TASK-60 — ошибка объясняется по-русски, а не строкой сервера

CLAUDE.md требует русского языка в сообщениях об ошибках. На экране печатается вот это:

```
Слот 2026-08-11T13:00:00+03:00 у врача d-003 уже занят (запись a-013)
Интервал 2026-08-11T13:00:00+03:00+30м не попадает в опубликованный рабочий шаблон врача d-003
Врач d-001 не оказывает услугу «ЭКГ»
Запись a-013 в статусе «no_show» неизменяема
```

Тексты собирает сервер (`stubs/api/appointments.js`), а клиент печатает их дословно:
`src/__data__/api.ts:75` `let message = serverMessage`. Готовые человеческие заготовки в
том же файле (в том числе «Выбранный слот уже занят») применяются, **только если сервер
молчит**. Вывод — `slot-card.tsx`, `registrar-page.tsx`, `patient-card-form.tsx`.

Путь достижим двумя кликами: в панели «Записать сразу на смену» у регистратора список
услуг не отфильтрован по врачу (`patient-card-form.tsx:396-399` рендерит все восемь), и
вместимость слота не проверяется — то есть на демо ошибку получают не специально, а
случайно.

Отдельно: поведение закреплено тестом. `src/__data__/api.test.ts:76-97` **требует**, чтобы
машинный текст попадал в `message` как есть, а `src/pages/operator/operator-page.test.tsx:168-169`
мокает сервер фразой «Выбранный слот уже занят», которой в стабах не существует —
экранный тест проверяет несуществующую реальность. Оба теста правятся вместе с кодом.

Тот же класс — латиница в журнале переходов: «Ожидает → Пришёл, **doctor**»
(`doctor-page.tsx:566`, `slot-card.tsx:693`); значения приходят из стаба литералами
`'operator'`, `'doctor'`, `'admin'`, `'system'`.

## Готовность

1. **Сообщение выбирается по коду ошибки, а не по тексту сервера.** `ApiError` уже несёт
   `code`; клиент подставляет человеческую формулировку по нему, серверный текст остаётся
   в полезной нагрузке для журнала. Тест: ответ сервера с машинным `message` и известным
   `code` даёт на выходе человеческую строку.
2. **Ни один код ошибки не остаётся без формулировки.** Тест перебирает все коды, которые
   умеют возвращать стабы (`slot_busy`, `outside_template`, `service_not_offered`,
   `terminal_status`, `equipment_busy`, `duplicate_patient`, …), и падает, если для кода
   нет русской строки.
3. **На экране не появляются внутренние идентификаторы и ISO-даты.** Тест на текст
   сообщения: нет подстрок вида `d-00`, `a-0`, `abs-`, `T00:00`, `+03:00`.
4. **Быстрая запись регистратора предлагает только услуги врача**, к которым у него есть
   допуск, и не даёт выбрать слот, в который запись не помещается. Тест: у врача без
   допуска к ЭКГ этой услуги в списке нет.
5. **Журнал переходов написан по-русски**: роль автора («оператор», «врач»,
   «администратор», «система») выводится через общий словарь рядом с `status-labels.ts`
   и применяется в АРМ врача и в карточке слота. Тест ищет латиницу в отрисованном
   журнале и падает на текущей реализации.
6. **Тест, требовавший машинный текст, переписан** на новый контракт: `api.test.ts`
   проверяет соответствие «код → человеческая строка», а мок в `operator-page.test.tsx`
   отвечает так же, как отвечает настоящий стаб.
