# TASK-17 — АРМ оператора: выбор не протекает между слотами, статистика честная

Две находки приёмки прогона `g_20260806-195014`:

- **P1: выбранный пациент протекает между слотами.** `patientId` инициализируется из
  записи только при первом монтировании ([slot-card.tsx:61]), а карточка переиспользуется
  без `key` при смене слота ([operator-page.tsx:191]). Открыл занятый слот, затем
  свободный — пациент первой записи уже выбран для новой, без действия оператора. Это
  запись не тому человеку, сделанная молча.
- **Нечестный гейт:** тест заявляет расчёт статистики смены из данных, но проверяет только
  статические подписи ([operator-page.test.tsx:269]). Захардкоженные значения останутся
  зелёными.

## Готовность

1. Смена выбранного слота полностью сбрасывает состояние карточки: у свободного слота
   пациент не выбран, независимо от того, что открывали до него.
2. Обзор смены (записей за смену, среднее время записи, требующие действия) считается по
   данным API; констант в компоненте нет.
3. Тесты доказывают оба пункта ЗНАЧЕНИЯМИ: после «занятый → свободный» поле пациента
   пусто, а при другом наборе записей числа в обзоре меняются. Оба теста падают при
   возврате прежнего поведения.
