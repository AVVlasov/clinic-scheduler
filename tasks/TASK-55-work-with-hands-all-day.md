# TASK-55 — в этом можно работать смену: клавиатура, отклик, подтверждение

Остальные задачи волны делают интерфейс правдивым и связным. Эта делает его пригодным для
восьмичасовой смены. Ни одна из TASK-36..54 не содержит слов «клавиатура», «фокус»,
«виртуализация», «производительность», «конфликт», «1366» — проверено grep по всем файлам
волны, `docs/` и `CLAUDE.md`. При этом всё перечисленное записано в нашей же
дизайн-системе, разделы 8–12.

Причина, по которой этот класс дефектов невидим: проверки задач — это vitest в jsdom, где
нет ни высоты экрана, ни фокуса, ни времени. Ровно так прошлый прогон закрыл 35 задач из
35 при мёртвом продукте.

## Замеры на живом приложении (1366×768)

- **Очередь регистратора: 8 строк, из них фокусируемых 0, с `role` — 0.** Визит нельзя
  выбрать с клавиатуры вообще.
- **Карточка визита регистратора: кнопка «Не пришёл» заканчивается на 741px при высоте
  окна 768.** Запас 27px, и **прокручиваемого предка у неё нет ни одного**. TASK-41
  добавляет в эту же карточку блок оплаты — кнопка уедет за экран без возможности
  доскроллить.
- **Сетка оператора: `SlotCell` не обёрнут в `React.memo`**, `onClick` создаёт новое
  замыкание на каждую ячейку при каждом рендере, `handleSlotClick` пересоздаётся при
  каждом выборе. Выбор слота перерисовывает всю сетку. TASK-37 вводит недельный режим —
  это семикратный рост числа ячеек.
- **Подтверждения успеха нет ни на одном АРМ:** `role="alert"` встречается в `src` один
  раз, и это ошибка. После «Записать» карточка просто исчезает.
- **Из экрана отказа загрузки нет выхода:** ранний возврат заменяет весь экран текстом,
  `Повторить` / `retry` в `src` не встречается ни разу. Единственная подсказка в продукте —
  «обновите страницу».

## Готовность

1. **Клавиатура.** От шапки до главного действия рабочего места не более 6 нажатий Tab на
   любом АРМ — тест считает табстопы. Стрелки перемещают выделение по сетке, Tab выходит
   из сетки целиком. Строка очереди регистратора выбирается с клавиатуры. Esc закрывает
   карточку, режим переноса и модалку из любого места.
2. **Ничего за краем экрана.** При 1366×768 у каждого рабочего места нет содержимого,
   недостижимого прокруткой: либо помещается, либо у него есть прокручиваемый предок.
   Тест проверяет это для карточки визита регистратора с заполненным блоком оплаты.
3. **Отклик.** От клика по слоту до отклика не более 100 мс при шести врачах и недельном
   режиме. Выбор слота перерисовывает выбранную и предыдущую ячейку, а не сетку —
   доказывается счётчиком рендеров. В DOM одновременно не более двух экранов строк сетки.
4. **Подтверждение действия.** Каждое успешное действие оставляет на экране строку с
   предметом действия. Тест: после создания записи на экране есть фамилия пациента и
   время слота; после отмены — указание освобождённого слота.
5. **Выход из ошибки.** Экран отказа загрузки содержит «Повторить»; нажатие восстанавливает
   экран без перезагрузки страницы и без потери выбранной даты.
6. **Двойной клик не создаёт двух записей.** Кнопка действия блокируется на время запроса.
   Тест: два клика подряд дают один POST.
7. **Необратимое действие подтверждается.** Отмена записи и «Не пришёл» требуют
   подтверждения с указанием, что именно будет сделано.

## Оговорка о доказуемости

Пункты 2 и 3 в jsdom не доказываются: там нет ни компоновки, ни времени. Их проверка
требует браузерного прогона (playwright как devDependency — правилами проекта разрешено).
Пока браузерного гейта нет, эти два пункта закрываются **человеком с замером в консоли**,
и это записывается в вердикт задачи. Объявлять их выполненными по зелёному jsdom нельзя —
это и есть тот способ, которым закрылись предыдущие 35 задач.
