# TASK-48 — приоритет источников дизайна: решение, потом токены

**Эту задачу нельзя отдать агенту целиком: первый пункт — решение владельца.**

Источников дизайна два, и они противоречат друг другу:

- `ai/05-дизайн/smclinic-Design-System.md` — документ, по которому построена реализация;
- `ai/05-дизайн/Clinic-scheduler UI макеты/_ds/` — рабочая сборка, **которой отрисованы
  сами макеты** и на которую смотрит заказчик.

Расхождения не косметические: шрифт (Golos Text против Open Sans), радиусы (999/12/8/6/4
против 40/4/0), веса (500/600 против 400/700), тени (три уровня против «теней нет»),
заливка занятого слота. Тридцать пять задач шли по документу, заказчик смотрел на макеты,
а гейт токенов закрепил один из двух источников как истину и с тех пор охраняет
расхождение.

Пока приоритет не установлен, правки радиусов, весов и плотности неисполнимы: любая
нарушает второй документ, и каждый круг приёмки спорит об этом заново.

## Готовность

1. **Решение владельца записано** в `CLAUDE.md`: какой из двух источников главный при
   расхождении и что делать со вторым. Без этой строки остальные пункты не начинать.
2. Расхождения между `smclinic-Design-System.md` и `_ds` перечислены в `docs/` списком:
   пять известных плюс всё, что найдётся при сверке. Для каждого — какой источник принят.
3. Токены темы собираются из принятого источника, а не переписываются в таблицу руками:
   расхождение между источником и `theme.tsx` обязано ломать тест.
4. Шрифты подключены. Сейчас `document.fonts.size === 0` — весь интерфейс отрисован
   системным шрифтом, то есть ни один из двух источников не выполнен. Файлы шрифтов и
   готовый `fonts.css` лежат в `_ds`.
5. Контраст текста на заливках соответствует принятому источнику. Белый текст 12px на
   `#F07A35` даёт 2.79:1 — это не проходит ни по одному из них.
