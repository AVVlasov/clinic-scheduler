# TASK-22 — регистратор: действия совпадают с машиной состояний, палитра не роняет очередь

Находка приёмки прогона `g_20260808-173152`, **P1**: интерфейс шлёт `status=scheduled` и для
«Отменить приход», и для «Восстановить» ([registrar-page.tsx:168]), а серверная машина
состояний из TASK-15 запрещает `arrived → scheduled` и `no_show → scheduled`. **Оба штатных
действия всегда заканчиваются 409 `invalid_state_transition`** — то есть кнопки на экране
есть, а работать они не могут ни разу.

Сюда же — вторая половина находки про `cancelled`: палитра статусов в очереди возвращает
`undefined` для неизвестного статуса, и обращение к `sp.bg` роняет рендер всей очереди.
Сам тип статуса чинит TASK-21.

## Файлы

- `src/pages/registrar/registrar-page.tsx`
- `src/pages/registrar/queue-table.tsx`
- `src/pages/registrar/transitions.test.tsx`

## Вход

TASK-21

## Готовность

1. Каждое действие очереди отправляет статус, допустимый машиной состояний из текущего
   статуса записи; недопустимых действий интерфейс не предлагает вовсе.
2. Палитра статусов имеет запасное значение: запись в любом статусе, включая `cancelled`,
   рендерится без исключения.
3. Тест доказывает оба пункта: «отменить приход» и «восстановить» уходят с допустимым
   статусом и не получают 409, а очередь с записью в `cancelled` рендерится целиком.
