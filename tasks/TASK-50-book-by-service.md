# TASK-50 — запись от услуги: сначала услуга, потом врач и слот

Основной сценарий оператора по ФТ, и он развёрнут в обратную сторону. Сейчас: выбрать
слот → услуга подставится первой из справочника. Требуется: выбрать услугу → система сама
покажет только тех врачей, кто её выполняет, реально работает в эту дату и имеет
свободное время.

ФТ ДКЦ1 описывает цену текущего порядка дословно: «оператору приходится сначала в базе
знаний посмотреть, какие врачи вообще оказывают услугу, потом идти в расписание и
проверять каждого врача вручную». ФТ С7, С12, ДКЦ3 добавляют то же для компетенций:
показывать только тех, у кого услуга разрешена с учётом возраста пациента.

В макете оператора это отдельные экраны: «Запись от услуги», «Опросник по услуге»,
«Подбор врача и слота», «Корзина», «Подтвердить запись». Сейчас недостижим ни один.

**Корзина в этой задаче не делается.** Множественная запись одной транзакцией — отдельный
объём (в смете это часть строки «UI: запись „от услуги“ → анкета → подбор → корзина»,
вторая очередь). Здесь — путь одной услуги, без которого корзину всё равно не построить.

## Готовность

1. Оператор начинает с услуги: есть поиск по справочнику услуг, и он ищет по названию и
   по категории (ФТ 9.8 «поиск услуги»).
2. После выбора услуги сетка показывает **только** врачей, которые эту услугу выполняют.
   Тест: услуга, доступная двум врачам из шести, оставляет в сетке две колонки.
3. Длительность берётся из выбранной услуги и резервирует нужное число слотов одной
   записью (см. TASK-40). Слоты, куда услуга не помещается, недоступны и объясняют почему.
4. Ограничения проверяются на сервере, а не только скрытием в интерфейсе: попытка
   записать на услугу к врачу без этой услуги отклоняется с кодом ошибки.
5. Прежний порядок «от слота» сохраняется и работает: оператор может начать и с сетки.
   Тест доказывает оба входа в один и тот же экран записи.
6. Сценарий `operator-book-by-service` зелёный и переведён в `required`.
