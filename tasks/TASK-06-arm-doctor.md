# TASK-06 — АРМ врача

Макет: `ai/05-дизайн/Clinic-scheduler UI макеты/ARM-doctor.dc.html`. День приёма и карточка
текущего пациента. Врач не уходит с этого экрана всю смену.

## Файлы

- `src/pages/doctor/index.ts`
- `src/pages/doctor/doctor-page.tsx`
- `src/pages/doctor/day-list.tsx`
- `src/pages/doctor/visit-form.tsx`
- `src/pages/doctor/doctor-page.test.tsx`

## Вход

TASK-02, TASK-04

## Готовность

1. Экран собран по макету: список приёмов на день со статусами, карточка пациента
   (дата рождения, uid, плательщик, телефон), форма приёма — жалобы, диагноз по МКБ-10,
   тип приёма, выполненные услуги со стоимостью, рекомендации и следующий визит.
2. Данные приходят из клиента API (TASK-04); выбор приёма из списка меняет карточку.
3. Тест доказывает: список пришёл из данных, выбор меняет карточку, «завершить приём»
   отправляет запрос и переводит приём в завершённый статус.

## Проверки

```
npx --no-install tsc --noEmit
npx --no-install eslint ./src --max-warnings=0
npx --no-install vitest run src/pages/doctor
```

## Что учесть

- Услуги и их стоимость берутся из справочника стабов, а не вводятся строкой.
- Незаполненные обязательные поля обязаны блокировать завершение приёма — это дешевле, чем
  визит, закрытый без диагноза.
