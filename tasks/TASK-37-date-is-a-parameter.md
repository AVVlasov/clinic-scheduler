# TASK-37 — дата: параметр системы, а не константа экрана

В системе три источника «сегодня», и ни одного согласования между ними:

- оператор датирует сетку сам — `todayDate()` внутри эффекта, изменить нельзя;
- записи он же получает по умолчанию сервера, то есть за другой день;
- регистратор печатает в шапке дату из браузера над данными сервера;
- врач не передаёт даты вообще.

Наблюдаемое следствие, ради которого задача и заведена: на одном экране оператора
одновременно написано «Сегодня выходной — смена не опубликована» и «8 записей в смене».
У регистратора шапка «Смена · 09.08.2026» стоит над очередью за 10.08. Экран не просто
пуст — он говорит неправду, а это дороже пустоты.

Дата обязана стать параметром: её задаёт человек, она видна в адресе, и все данные
экрана берутся ровно за неё.

## Готовность

1. `GET /appointments` без параметра `date` отвечает **400**. Молчаливый дефолт убран:
   именно он позволял экрану показывать чужой день, не зная об этом.
2. Ответ `/appointments` содержит поле `date`, оно есть в типе `AppointmentList`, и
   клиент сверяет его с запрошенным — расхождение показывается как ошибка, а не молча.
3. Выбранная дата живёт в адресе рабочего места (`?date=ГГГГ-ММ-ДД`); открытая ссылка
   восстанавливает тот же день. Без даты в адресе открывается сегодня.
4. В шапке рабочего места есть переключатель дня: назад, вперёд, «сегодня». Он есть на
   всех трёх АРМ, где данные привязаны ко дню (оператор, регистратор, врач).
   **Назад — без ограничения по прошлому** (ФТ С18: «в календаре отсутствует удобный
   переход назад, навигация ограничена только вперёд или текущим месяцем»).
5. У оператора переключатель диапазона **«Сегодня · Завтра · Неделя»** — ровно эти три
   значения из макета (`ranges: [['today','Сегодня'],['tomorrow','Завтра'],['week','Неделя']]`
   в `ARM-operator.dc.html`). Недельный режим — не украшение: «сетка расписания
   (**неделя**/день)» стоит в MUST HAVE первой очереди (бэклог, строка 17), а дневная
   сетка одна закрывает половину требования.
   Тест: переключение в «Неделя» показывает семь дней; выбор слота в недельном режиме
   ведёт в ту же карточку записи, что и в дневном.
6. Все блоки экрана берут данные за одну и ту же дату. Тест: сетка пуста ⟹ «Обзор
   смены» показывает нули, а не число записей другого дня. Сейчас это соседствует.
7. Сквозной сценарий `operator-book` **зелёный**: сетка открывается, свободные слоты
   есть, пациент выбирается, запись создаётся и видна на сервере.
