# TASK-31 — администратор: экран не показывает данные прошлого запроса

Две находки приёмки прогона `g_20260808-192745` (**P1**), обе про состояние во время
загрузки — и обе внесены прошлым кругом правок:

- **Переключение недели оставляет старые шаблоны на экране**: `templates` и `published`
  принадлежат предыдущей неделе, а `weekStart` уже новый. Между двумя неопубликованными
  неделями кнопка остаётся активной, подтверждение показывает **прежний** диапазон, а
  `publishWeek` отправляет **новый** `weekStart` — то есть необратимо публикуется не та
  неделя, которую человек видел в подтверждении.
- **Сохранение врача затирает черновик другого врача** ([admin-page.tsx:149]): ответ
  безусловно заменяет общий `draft`. Список остаётся доступен во время запроса — сохранили
  A, выбрали B до ответа, и под заголовком B появляются поля A; следующее сохранение
  записывает их в карточку B.

## Готовность

1. При смене недели данные предыдущей немедленно перестают показываться: экран в
   состоянии загрузки, публикация недоступна, подтверждение называет ту же неделю, что
   уйдёт в запрос.
2. Ответ на сохранение применяется, только если относится к текущему выбранному врачу;
   ответ по устаревшему выбору отбрасывается.
3. Тест доказывает обе гонки: публикация после переключения уходит с показанной неделей,
   а поздний ответ сохранения не подменяет поля выбранного врача.
