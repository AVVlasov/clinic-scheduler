# TASK-07 — АРМ оператора: сетка расписания

Макет: `ai/05-дизайн/Clinic-scheduler UI макеты/ARM-operator.dc.html`. Самый нагруженный
экран системы: оператор ищет слот и записывает по телефону, пока пациент на линии. Бюджет —
сетка за 1 секунду, поиск слота за 0,5.

## Файлы

- `src/pages/operator/index.ts`
- `src/pages/operator/operator-page.tsx`
- `src/pages/operator/schedule-grid.tsx`
- `src/pages/operator/slot-card.tsx`
- `src/pages/operator/shift-overview.tsx`
- `src/pages/operator/operator-page.test.tsx`

## Вход

TASK-02, TASK-04

## Готовность

1. [x] Сетка ресурсов с шагом 15 минут по данным стаба: строки — врачи и оборудование, колонки —
   время; занятые слоты видны заливкой записи, свободные — кликабельны.
2. [x] Клик по слоту открывает карточку: время, врач, специальность, пациент, услуга, ресурсы,
   автор записи; из карточки доступны «записать» и «перенести», обе через клиент API.
3. [x] Тест доказывает: сетка построена из данных (а не из констант), клик по свободному слоту
   открывает карточку, запись в занятый слот показывает ошибку конфликта, а не молча
   перезаписывает.

## Что учесть

- Сетка на день — это сотни ячеек. Перерисовка всей сетки на выбор одного слота съедает
  весь бюджет отклика: выбор держать локальным состоянием ячейки/строки.
- Обзор смены сверху (записей за смену, среднее время записи, требующие действия) — часть
  макета, не украшение.
