# TASK-58 — перенос попадает в тот день, который выбрал оператор

Перенос записи — одно из двух действий АРМ оператора по PRD. В режиме «Неделя» он
переносит пациента не туда.

`slot-card.tsx:283` строит цель как `buildStartIso(scheduleDate, rescheduleTargetTime)`,
где `scheduleDate` — дата **исходной** записи. В карточку передаются только
`rescheduleTarget?.time` и `?.doctorId`; поле `date`, которое проставляется в
`setRescheduleTarget`, в `SlotCardProps` отсутствует вовсе. Подсветка цели при этом
рисуется по правильному дню — интерфейс выглядит корректно, а PATCH уходит в исходный.

Сценарий, который сломается на показе: «перенесите пациента со вторника на четверг».
Оператор кликает четверг 15:00, ячейка подсвечивается, жмёт «Перенести» — запись уезжает
на вторник 15:00. Свободно там — пациент молча оказывается не в том дне; занято — вылетит
машинная строка сервера. Кросс-дневной перенос не покрыт ни одним тестом:
`operator-reschedule.journey.test.tsx` работает внутри одного дня.

Рядом три дефекта того же экрана, из-за которых оператор не понимает, что происходит:

- **Из режима переноса нельзя выйти кликом.** После просмотра занятой записи клик по
  свободному слоту уходит в `setRescheduleTarget` и делает `return`, `setSelected` не
  вызывается (`operator-page.tsx:222-238`). Карточка продолжает показывать чужую запись;
  выход — только Escape или кнопка «Сбросить перенос».
- **Выбранный слот не выделен.** Проп `selected` используется ровно один раз — как
  `data-selected` (`schedule-grid.tsx:199`), а CSS-правила на этот атрибут в проекте нет.
  Цель переноса подсвечена оранжевым, исходный выбранный слот — ничем.
- **«Завтра» не слушает дату шапки**: `[shiftDate(todayDate(), 1)]` вместо `selectedDate`
  (`operator-page.tsx:88-92`), поэтому шапка показывает одно число, а сетка другое.
  Плюс зелёное «Запись создана: …» не исчезает никогда — `setActionNotice` нигде не
  сбрасывается.

## Готовность

1. **Перенос между днями попадает в выбранный день.** Сквозной сценарий на настоящих
   стабах: запись во вторник, диапазон «Неделя», цель — четверг 15:00; после «Перенести»
   `GET /appointments` за четверг содержит запись на 15:00, за вторник — не содержит.
   Тест падает без изменения кода.
2. **Дата цели доезжает до карточки типом, а не догадкой**: `SlotCardProps` содержит дату
   цели переноса, и карточка не может собрать `targetIso` из чужой даты. Проверяется
   `tsc` и тестом на компонент.
3. **Клик по свободному слоту в режиме переноса выбирает его целью, а клик по другой
   занятой записи открывает её карточку** — оператор выходит из режима переноса, не
   вспоминая про Escape. Тест на два последовательных клика.
4. **Выбранный слот видно.** Выбор меняет заливку либо рамку ячейки (проверяется по
   вычисленному стилю, а не по наличию атрибута), и это состояние отличается от
   подсветки цели переноса.
5. **«Завтра» считается от даты, выбранной в шапке**, и подпись сетки совпадает с датой
   шапки. Тест: шапка на 10.08, «Завтра» → сетка на 11.08.
6. **Сообщение об успехе живёт ограниченно**: после следующего действия оператора
   или смены дня плашка «Запись создана» исчезает. Тест проверяет отсутствие старого
   уведомления после смены даты.
