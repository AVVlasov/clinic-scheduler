# TASK-05 — АРМ регистратора

Макет: `ai/05-дизайн/Clinic-scheduler UI макеты/ARM-registrar.dc.html`. Смена регистратора —
это очередь у стойки: приход, оплата, талон. Экран обязан отвечать на вопрос «кто следующий»
без прокрутки.

## Файлы

- `src/pages/registrar/index.ts`
- `src/pages/registrar/registrar-page.tsx`
- `src/pages/registrar/queue-table.tsx`
- `src/pages/registrar/visit-card.tsx`
- `src/pages/registrar/registrar-page.test.tsx`

## Вход

TASK-02, TASK-04

## Готовность

1. Экран собран по макету: шапка смены со счётчиками (ожидают приёма, отмечено приходов,
   касса), очередь смены с фильтрами и колонками «время / пациент / врач и услуга / оплата /
   статус», карточка выбранного визита с документами и суммой к оплате.
2. Данные приходят из клиента API (TASK-04), а не из констант в компоненте; выбор строки
   очереди меняет карточку визита.
3. Тест рендерит экран на данных стаба и доказывает: строки очереди пришли из данных, выбор
   строки меняет карточку, действие «отметить приход» отправляет запрос и обновляет статус.
