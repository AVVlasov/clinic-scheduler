# TASK-04 — типы домена и клиент API

Четыре экрана будут ходить в одни и те же маршруты. Если клиент напишет каждый сам, домен
разъедется по четырём файлам: одна и та же запись станет тремя разными типами, и первая же
правка стаба сломает три экрана из четырёх молча.

## Файлы

- `src/__data__/types.ts`
- `src/__data__/api.ts`
- `src/__data__/urls.ts`
- `src/__data__/api.test.ts`

## Вход

TASK-03

## Готовность

1. `types.ts` описывает домен по ответам стабов: слот, ресурс (врач/оборудование), запись,
   пациент, услуга, статусы записи и типы оплаты.
2. `api.ts` даёт типизированные функции чтения и изменения (сетка на дату, записи смены,
   справочники, создание и перенос записи) поверх адреса из конфигурации `bro.config.js`
   (`clinic-scheduler.api`), с разбором ошибочных ответов.
3. Тест доказывает: успешный ответ разбирается в типы, а ответ 409 при записи в занятый
   слот превращается в понятную ошибку, а не в исключение сети.

## Проверки

```
npx --no-install tsc --noEmit
npx --no-install eslint ./src --max-warnings=0
npx --no-install vitest run src/__data__/api.test.ts
```

## Что учесть

- Адрес API берётся из `@brojs/cli` (`getConfigValue`), а не зашивается строкой: в prom-режиме
  он другой.
- В тесте сеть не поднимается — `fetch` подменяется на уровне теста; проверяется разбор, а не
  доступность сервера.
