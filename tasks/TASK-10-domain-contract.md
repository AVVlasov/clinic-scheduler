# TASK-10 — домен визита: протокол приёма, стоимость услуг, контракт ошибок

Находки приёмки прогона `g_20260806-151836` (критик «склейка»). Четыре из шести дефектов
живут не в экранах, а в общем домене — поэтому чинятся здесь, до правки самих экранов.

- **Протокол приёма некуда сохранить.** `PATCH /appointments/:id` не принимает жалобы,
  диагноз, выполненные услуги и рекомендации: [types.ts:89]. АРМ врача закрывает приём
  одним `{ status: 'completed' }`, и после перезагрузки протокол исчезает.
- **У услуги нет цены.** Справочник её не отдаёт ([data.js:25]), поэтому АРМ врача
  вычисляет стоимость из длины названия и длительности, а регистратор показывает
  константу. Два экрана называют разные деньги за одну услугу.
- **Ошибки трактуются по-разному.** Клиент ждёт машинный код в `error` и текст в
  `message` ([api.ts:39]), а стаб кладёт русское предложение прямо в `error`
  ([appointments.js:43]): UI показывает «Не удалось выполнить запрос», а код ошибки
  становится фразой.
- **Тип `Doctor` не соответствует ответу стаба.**

## Готовность

1. Услуга отдаётся с ценой, а типы домена совпадают с реальными ответами стабов (включая
   `Doctor`); стоимость визита считается по справочнику, а не выводится из названия.
2. `PATCH /appointments/:id` принимает и сохраняет протокол приёма — жалобы, диагноз по
   МКБ-10, тип приёма, выполненные услуги, рекомендации — и отдаёт их обратно в `GET`.
3. Ошибка API несёт стабильный машинный код отдельно от текста для человека; клиент
   различает конфликт слота, отсутствие обязательных полей и сетевой отказ.

## Что учесть

- Тесты обязаны падать без изменения кода: сохранение протокола проверяется циклом
  «записал → прочитал», а не наличием поля в типе.
- Формат кода ошибки выбрать один и записать его в тип: `SLOT_TAKEN`, `VALIDATION`,
  `NETWORK` — и далее использовать только его.
