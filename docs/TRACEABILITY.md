# Прослеживаемость: требование → сценарий → задача

Составлена 2026-08-09 сверкой плана с документами заказчика: `ai/01-требования/ФТ_118_требований.docx`,
`MVP_MAP.docx`, `FAQ_заказчика.docx`, `Атрибуты_записи_по_сценариям.xlsx`,
`ai/02-оценка/Бэклог_задач.xlsx` и макетами `ai/05-дизайн/Clinic-scheduler UI макеты/*.dc.html`.

**Зачем.** Первая волна закрыла 35 задач из 35 и напечатала «COMPLETE» при продукте, в
котором не работал ни один клиентский путь. Причина не в качестве проверок: они отвечали
на вопрос «дерево в порядке». Вопрос «покрыто ли требование заказчика» не задавал никто —
в `docs/PRD.md` нет ни одной ссылки на номер требования ФТ. Эта таблица и есть такая
ссылка; её читают на приёмке вместо отчёта о закрытых задачах.

**Как читать.** Пустая клетка в колонке «задача» означает одно из двух: либо задача ещё
не заведена (пробел), либо решение владельца «вторая очередь» с основанием. Третьего
состояния — «как-нибудь потом» — быть не должно.

## Что перепроверить перед приёмкой

1. Таблица составлена по извлечённому тексту документов. Спорные строки сверить с
   оригиналами `.docx` и `.xlsx`, а не с извлечением.
2. Колонка «задача» проверяется командой, а не глазами: у задачи должны быть проверки в
   `config/checks.json`, и они должны быть зелёными.
3. Строка без сценария — кандидат в «нечем доказать». Требование, закрытое задачей без
   сценария, доказано на уровне кода, а не работы пользователя.
